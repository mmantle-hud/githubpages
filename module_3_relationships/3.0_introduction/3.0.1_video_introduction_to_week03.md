# Video: Introduction to Week 3 Relationships




So far in the course we have only considered single table databases. My course assessment example had a single table, students. The board games example had a single board games table. However, in anything other than really simple applications, we are going to need more than one table. Going back to our e-commerce web application example. Our database would need to store data about the products we are selling, the product categories, the customers, and the orders customers place. We would use separate tables to store data about each of these entities. These entities: products, categories, customers and orders are related, they are linked. A product belongs to a category. A customer places an order. An order is made up of a number of different products. An important part of relational databases is being able to store data about relationships and this is exactly what will look at this week. We will learn about different types of relationship such as one-to-many relationships and many-to-many relationships, and how to capture relationships in database tables using foreign keys. We will also develop further SQL skills by using joins to select data from multiple related tables. Finally, this week will be our first introduction to Entity Relationship Diagrams (ERDs). These are an important way for database professionals to map out and visualise the entities and relationships within a database. There's a lot to go through this week, and in my experience most students find relationships and joins to be in a step-up in difficulty compared to the early weeks of the course. Please stick with it. If you can master these ideas of relationships, foreign keys and sql joins you will find many of the topics we look at in future weeks are much easier to understand.
