# Another Many-to-Many Relationship
Building on our board games example, we could add board game mechanisms to our database to help users decide what game they would like to play. 

> A board game mechanism is simply the way in which the game is played. For example, by rolling dice, placing tiles on a board or by collecting sets, cards or items.  

There is a many-to-many (M:M) relationship between board games and mechanisms:
- A single board games can use **many** mechanisms. For example, the game Monopoly uses dice rolling and trading as mechanisms.  
- A single mechanism can be used by **many** different board games. For example Monopoly, Backgammon and Yahtzee all use dice rolling. 

Here's an ERD showing these relationships.

And an example query

```sql
SELECT bg.game_title,
    m.mechanism_name
FROM board_games AS bg
    INNER JOIN board_game_mechanism AS bgm ON bg.board_game_id = bgm.board_game_id
    INNER JOIN mechanisms AS m ON bgm.mechanism_id = m.mechanism_id;
```
