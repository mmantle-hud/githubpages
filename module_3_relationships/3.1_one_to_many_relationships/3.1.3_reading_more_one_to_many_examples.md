# More One-to-Many Relationship Examples
When learning relational database concepts such as relationships and joins, it can help to see a number of different examples. Here are some more examples of 1:M relationships.

## Publisher and Board Game
Previously, we looked at a board game database that stored the title, release year, playing time and number of players for each board game. We can now expand this scenario to also record the publisher of the game. Publishers are companies that manage the production and distribution of the board game.  

There is one-to-many (1:M) relationship between publisher and board game:
- A single board game is published by **one** publisher. 
- A single publisher can publish **many** different board games.

We follow the same pattern we have seen previously. We add a foreign key to the `board_games` table to link each game to a publisher.

```s
ql
SELECT bg.game_title,
    bg.release_year,
    p.publisher_name

FROM board_games AS bg
    INNER JOIN publishers AS p ON bg.publisher_id = p.publisher_id;
```

## Football Teams and Matches
Think about the relationship between football teams and the matches they play:
- A team plays in **many** matches. 
- A match is played by **two** teams. 

We can differentiate between the home team and away team that play in a match giving us two distinct one-to-many relationships.
1. A team plays as the home team in **many** matches. A single match is played by **one** home team. 
2. A team plays as the away team in **many** matches. A single match is played by **one** away team. 

In the _matches_ table we will need two foreign keys. One for the home team. One for the away team. 

<pre class="mermaid">
erDiagram
    teams||--o{matches : "plays as home team"
    teams||--o{matches : "plays as away team"
    teams{
        INT team_id PK
        VARCHAR(255) team_name
    }
    matches{
        INT match_id PK
        TIMESTAMP match_date
        INT home_team_id FK 
        INT away_team_id FK
        SMALLINT home_team_score 
        SMALLINT away_team_score
    }
</pre>

Here are some example tables.

**teams**

|---------|---------------------| 
| 1       | Real Madrid         | 
| 2       | Manchester City     | 
| 3       | Barcelona           | 
| 4       | Paris Saint-Germain | 
| 5       | Liverpool           | 
| 6       | Roma                | 

**matches**

| match_id (PK) | match_date          | home_team_id | away_team_id | home_team_score (FK) | away_team_score (FK) | 
|----------|---------------------|--------------|--------------|-----------------|-----------------| 
| 1        | 2017-03-08 20:45:00 | 3            | 4            | 6               | 1               | 
| 2        | 2019-05-07 21:00:00 | 5            | 3            | 4               | 0               | 
| 3        | 2022-05-04 21:00:00 | 1            | 2            | 3               | 1               | 
| 4        | 2018-04-10 20:45:00 | 6            | 3            | 3               | 0               | 

We use `TIMESTAMP` to store the exact time and date of the football match. The `TIMESTAMP` data type used to record a precise, specific moment in time. We can think of it as a combination of date and time.

We can query by joining the `matches` table to the `teams` table twice.

```sql
SELECT
    h.team_name AS home_team,
    a.team_name AS away_team,
    m.home_team_score AS home_score,
    m.away_team_score AS away_score,
    m.match_date AS date
FROM
    matches AS m
    INNER JOIN teams AS h ON m.home_team_id = h.team_id
    INNER JOIN teams AS a ON m.away_team_id = a.team_id;
```
