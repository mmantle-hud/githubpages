# Video: Introduction to Normalisation

This week we are continuing to explore the topic of database design by looking at normalisation. 

The process of normalisation involves running a series of tests on a database to see if it has design flaws. 

We can see normalisation as being like running a number of checks on a car to see if it is roadworthy before driving it. For example, we would check the tyre presure, check the brakes and lights work and so on. Normalisation is the same idea but for databases. 

Each test or check we do on a database is called a normal form, and we use phrases such as the database is in second normal form, meaning it's passed the first two checks. 

There are many normal forms. The good news is we only need to know about the first three. The first three normal forms are good enough to catch many database design issues. The later normal forms are important, but tend to test for rarely seen problems.

The final thing worth saying in this introduction is although normalisation is a really useful tool for us as database designers, it doesn't catch or fix all database design problems. We still need to use our judgement and give though to issues such as data redundency and consistnency when designing our tables.
