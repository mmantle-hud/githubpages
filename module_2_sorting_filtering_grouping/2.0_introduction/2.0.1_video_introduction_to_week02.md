# Video: Introduction to Week 2
Last week we looked at key SQL commands CREATE, INSERT, UPDATE, DELETE and SELECT. We learned how to create tables, populate them with data, query tables and modify and delete rows. 

This week we are going to do a deeper exploration of just one type of SQL statement, the SELECT statement. There's a lot more to the SELECT statement than we covered last week. In fact, database professionals write far more SELECT queries than any other type of SQL statement. 

To give you some idea, imagine we are building an e-commerce website where we store data like product details and customer orders in database tables. 

Some typical tasks we might want to perform would be finding the best selling products, or finding customers that haven't placed an order recently, or we may want to provide a search facility on our website where we retrieve products that match a user entered search term. 

These tasks involve filtering and sorting. Filtering a table means only retrieving rows that match certain conditions. For example, only the rows where the product name matches a search term the user has entered. 

Sorting means arranging the results in a specific order. For example, ordering products by the number of sales. 

The first part of this week will cover various ways in which we can filter and sort data using the SELECT statement.

The second part of this week will then go on to look at grouping and aggregations. Aggregate functions allow us to perform a calculation over multiple rows. For example, to tell us the average price of the products in our database, or to add up the total number of sales in the last month. 

Grouping merges multiple rows so we can perform these aggregate calculations. For example, we could group products based on the product category and then report the number of products in each category or the cheapest product in each category. We might group sales by date which would then allow us to view trends in the data over time. 

Just like filtering and sorting, grouping and aggregations are also implemented using the SELECT statement. 

Finally, I think the best way to learn these features of SQL is to write your own queries. So my advice when approaching this week is to briefly look over the reading to get an overview of the topic, and then attempt the lab work where you will write SQL. If you get stuck or aren't sure how to answer one of the lab questions, then look back at the reading to try and find a similar example. 

I think this more problem oriented approach to learning SQL is more productive than spending a long time reading through the notes and trying to digest and remember every example.
