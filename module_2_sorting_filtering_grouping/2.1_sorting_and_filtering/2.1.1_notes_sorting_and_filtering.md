There's much more to the `SELECT` statement. You will write far more queries to select data than any other type of database command. The following describes some key features of `SELECT`.

## Sorting
We can sort the results returned by our queries and restrict how many queries are returned. 

### `ORDER BY`
We can sort results numerically and alphabetically using ```ORDER BY```. The default ordering is ascending order i.e. smallest to largest. In the following query we add ```DESC``` for descending order.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |
| Donald     | Chamberlin    | 85   |
| Elizabeth  | Fong          | 67   |
| Jennifer   | Widom         | 47   |
| Michael    | Stonebraker   | 34   |

We can perform multiple levels of ordering by listing multiple columns, separated by commas.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC, family_name ASC;
``` 

| given_name | family_name | score | 
|------------|-------------|------| 
| Edgar      | Codd        | 92   | 
| Donald     | Chamberlin  | 85   | 
| Patricia   | Selinger    | 85   | 
| Elizabeth  | Fong        | 67   | 
| Michael    | Stonebraker | 34   | 
| Jennifer   | Widom       | 47   | 
 
Donald Chamberlin now appears before Patricia Selinger in the results. 

### `LIMIT`
We can specify the number of results to return. For example, to only retrieve the two students with the highest scores.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC 
  LIMIT 2;
```
| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |

We can also deal with ties. Because Patricia Selinger and Donald Chamberlin both scored 85, the following query will return three rows even though we've only asked for two. 

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC
FETCH FIRST 2 ROWS WITH TIES;
```
| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |
| Donald     | Chamberlin    | 85   |

### OFFSET
```OFFSET``` allows us to skip records
```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC
  OFFSET 3;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Elizabeth  | Fong          | 67   |
| Jennifer   | Widom         | 47   |
| Michael    | Stonebraker   | 34   |

The students with the three highest scores (Edgar, Donald, Patricia) have been skipped. ```OFFSET``` is used for pagination, splitting search results over several pages. When a user is viewing the third page of results we run a query that skips past the results that have already been displayed. 


## Filtering
We can filter the results returned by a query in a number of different ways.

### `DISTINCT`
- The ```DISTINCT``` key word is used to filter out duplicate rows

```sql
SELECT DISTINCT degree FROM students;
```
| degree                  |
|-------------------------|
| Data Science            |
| Information Technology  |
| Computing               |

There are multiple students on Computing and Data Science, but we only show each degree title once in the results. 

### `WHERE`
- The ```WHERE``` clause is our main way of filtering results.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE degree = 'Computing';
```
| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |

This ```WHERE``` clause uses an equality condition (`=`). We can also test if two expressions are not equal. This query retrieves all the students that aren't studying Computing.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE degree <> 'Computing';
```

| given_name | family_name   | score |
|------------|---------------|------|
| Elizabeth  | Fong          | 67   |
| Donald     | Chamberlin    | 85   |
| Michael    | Stonebraker   | 34   |
| Jennifer   | Widom         | 47   |

We can use many of the conditional operators that you should be familiar with from studying Python. This query retrieves all the students that have failed the course i.e. they have a score less than 40. 

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE score < 40;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Michael    | Stonebraker   | 34   |


We can also use the logical operators ```AND``` and ```OR```. This query selects all the students that got a B grade (a score in the 60s).

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE score >= 60 AND score < 70;
```
| given_name | family_name   | score |
|------------|---------------|------|
| Elizabeth  | Fong          | 67   |

### Filtering by membership ```IN``` and ```NOT IN```
The ```IN``` and ```NOT IN``` operators allow us to filter using a list of values. 

This query selects students that are studying a number of different degrees.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE degree IN ('Computing','Software Engineering','Information Technology');
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |
| Donald     | Chamberlin    | 85   |
| Jennifer   | Widom         | 47   |

```NOT IN``` works in the same way, but is used to exclude rows from the results.

### Fuzzy Matching using `LIKE` and `ILIKE`
The ```LIKE``` operator can be used to perform fuzzy matching on text data. 

This query retrieves all the rows where the family name begins with 'C'.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE family_name LIKE 'C%';
```
| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Donald     | Chamberlin    | 85   |

The percent sign (%) acts as a wildcard. We can use wildcards in different ways:
  - '%n' Find all the strings that end in 'n'
  - '%in%' Find all the strings that contain the substring 'in'

The ```LIKE``` operator is case-sensitive. If we want to do a case-insensitive search we use ```ILIKE```. 

## Filtering and NULL

Imagine Jennifer Widom didn't submit any assignment work. She has a value of NULL for score. 

|student_id| given_name | family_name   | degree                  | score |
|----------|------------|---------------|-------------------------|------|
|1         | Edgar      | Codd          | Computing               | 92   |
|2         | Elizabeth  | Fong          | Data Science            | 67   |
|3         | Patricia   | Selinger      | Computing               | 85   |
|4         | Donald     | Chamberlin    | Information Technology  | 85   |
|5         | Michael    | Stonebraker   | Data Science            | 34   |
|6         | Jennifer   | Widom         | Computing               | NULL |

If we want to find out the top scoring students we would run the following query.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC
  LIMIT 2;
```
| given_name | family_name   | score |
|------------|---------------|------|
| Jennifer   | Widom         | NULL |
| Edgar      | Codd          | 92   |

Jennifer Widom appears top of our results. PostgreSQL treats NULL values as "larger" than any number or text value! To fix this we can add a ```WHERE IS NOT NULL``` filter.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE score IS NOT NULL
  ORDER BY score DESC LIMIT 2;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |

We should always check which columns are nullable when filtering.
