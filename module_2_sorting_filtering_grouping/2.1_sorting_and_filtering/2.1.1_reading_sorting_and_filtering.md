# Sorting and Filtering in SQL
Previously, we looked at a simple database for storing student scores.

**students**

|student_id (PK)| given_name | family_name   | degree                  | score |
|----------|------------|---------------|-------------------------|------|
|1         | Edgar      | Codd          | Computing               | 92   |
|2         | Elizabeth  | Fong          | Data Science            | 67   |
|3         | Patricia   | Selinger      | Computing               | 85   |
|4         | Donald     | Chamberlin    | Information Technology  | 85   |
|5         | Michael    | Stonebraker   | Data Science            | 34   |
|6         | Jennifer   | Widom         | Computing               | 47   |

We looked briefly at the ```SELECT``` statement e.g.

```sql
SELECT 
  given_name, 
  family_name, 
  degree 
FROM students;
```

| given_name | family_name   | degree                  |
|------------|---------------|-------------------------|
| Edgar      | Codd          | Computing               |
| Elizabeth  | Fong          | Data Science            |
| Patricia   | Selinger      | Computing               |
| Donald     | Chamberlin    | Information Technology  |
| Michael    | Stonebraker   | Data Science            |
| Jennifer   | Widom         | Computing               |

There's much more to the `SELECT` statement. The following describes key features of `SELECT` that allow us to sort and filter data.


## Sorting
We can sort the results returned by our queries and restrict how many rows are returned. 

### ORDER BY
We can sort results numerically and alphabetically using ```ORDER BY```. The default ordering is ascending order i.e. smallest to largest. In the following query we add ```DESC``` to sort the student scores in descending order.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |
| Donald     | Chamberlin    | 85   |
| Elizabeth  | Fong          | 67   |
| Jennifer   | Widom         | 47   |
| Michael    | Stonebraker   | 34   |

We can perform multiple levels of ordering by listing multiple columns, separated by commas.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC, family_name ASC;
``` 

| given_name | family_name | score | 
|------------|-------------|------| 
| Edgar      | Codd        | 92   | 
| Donald     | Chamberlin  | 85   | 
| Patricia   | Selinger    | 85   | 
| Elizabeth  | Fong        | 67   | 
| Jennifer   | Widom       | 47   | 
| Michael    | Stonebraker | 34   | 
 
`family_name` is only used to order rows where score is tied. Donald Chamberlin now appears before Patricia Selinger in the results. 

### LIMIT
We can specify the number of results to return. For example, to only retrieve the two students with the highest scores.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC 
  LIMIT 2;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |

We can also deal with ties. Because Patricia Selinger and Donald Chamberlin both scored 85, the following query will return three rows even though we've only asked for two. 

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC
FETCH FIRST 2 ROWS WITH TIES;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |
| Donald     | Chamberlin    | 85   |

### OFFSET
```OFFSET``` allows us to skip records
```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC
  LIMIT 3
  OFFSET 3;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Elizabeth  | Fong          | 67   |
| Jennifer   | Widom         | 47   |
| Michael    | Stonebraker   | 34   |

The students with the three highest scores (Edgar, Donald, Patricia) have been skipped. 

```OFFSET``` is used for pagination, splitting search results over several pages. When a user is viewing a later page of results, we can use OFFSET to skip past rows that have already been displayed.


## Filtering
We can filter the results returned by a query in a number of different ways.

### DISTINCT
The ```DISTINCT``` keyword is used to remove duplicate rows.

```sql
SELECT DISTINCT degree FROM students;
```

| degree                  |
|-------------------------|
| Data Science            |
| Information Technology  |
| Computing               |

There are multiple students on Computing and Data Science, but we only show each degree title once in the results. 

### WHERE
The ```WHERE``` clause is our main way of filtering results.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE degree = 'Computing';
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |


This ```WHERE``` clause used an equality condition (`=`). 

We can also test if two expressions are not equal (`<>`). The following query retrieves all the students that aren't studying 'Computing'.

```sql
SELECT 
  given_name, 
  family_name, 
  degree,
  score FROM students
  WHERE degree <> 'Computing';
```

| given_name | family_name   |degree                  | score |
|------------|---------------|------------------------|-------|
| Elizabeth  | Fong          | Data Science           |67     |
| Donald     | Chamberlin    | Information Technology |85     |
| Michael    | Stonebraker   | Data Science           |34     |


We can use many of the conditional operators that you should be familiar with from studying Python. 

This query retrieves all the students that have failed the course i.e. they have a score less than 40. 

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE score < 40;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Michael    | Stonebraker   | 34   |


We can also use the logical operators ```AND``` and ```OR```. 

This query selects all the students that got a B grade (a score in the 60s).

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE score >= 60 AND score < 70;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Elizabeth  | Fong          | 67   |

### Filtering by membership IN and NOT IN
The ```IN``` and ```NOT IN``` operators allow us to filter using a list of values. 

This query selects students that are studying a number of different degrees.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE degree IN ('Computing','Software Engineering','Information Technology');
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Patricia   | Selinger      | 85   |
| Donald     | Chamberlin    | 85   |
| Jennifer   | Widom         | 47   |

```NOT IN``` works in the same way, but is used to exclude rows from the results.

### Pattern Matching using LIKE and ILIKE
The ```LIKE``` operator can be used to perform pattern matching on text data. 

This query retrieves all the rows where the family name begins with 'C'.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE family_name LIKE 'C%';
```

| given_name | family_name   | score |
|------------|---------------|------|
| Edgar      | Codd          | 92   |
| Donald     | Chamberlin    | 85   |

The percent sign (%) acts as a wildcard. We can use wildcards in different ways:
  - '%n' Find all the names that end in 'n'. Selects 'Chamberlin'
  - '%in%' Find all the names that contain the substring 'in'. Selects 'Selinger' and 'Chamberlin'

The ```LIKE``` operator is case-sensitive. If we want to perform a case-insensitive search we use ```ILIKE```. 


## Filtering and NULL

Imagine Jennifer Widom didn't submit any assignment work. She has a value of NULL for score. 

|student_id (PK) | given_name | family_name   | degree                  | score |
|----------|------------|---------------|-------------------------|------|
|1         | Edgar      | Codd          | Computing               | 92   |
|2         | Elizabeth  | Fong          | Data Science            | 67   |
|3         | Patricia   | Selinger      | Computing               | 85   |
|4         | Donald     | Chamberlin    | Information Technology  | 85   |
|5         | Michael    | Stonebraker   | Data Science            | 34   |
|6         | Jennifer   | Widom         | Computing               | NULL |

If we want to find the top scoring students we could run the following query.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  ORDER BY score DESC
  FETCH FIRST 2 ROWS WITH TIES;
```

| given_name | family_name   | score |
|------------|---------------|------|
| Jennifer   | Widom         | NULL |
| Edgar      | Codd          | 92   |

Jennifer Widom appears top of our results. PostgreSQL's default ordering puts NULL values last for ASC and first for DESC!

To fix this we can add a ```WHERE IS NOT NULL``` filter.

```sql
SELECT 
  given_name, 
  family_name, 
  score FROM students
  WHERE score IS NOT NULL
  ORDER BY score DESC
  FETCH FIRST 2 ROWS WITH TIES;
```

| given_name | family_name   | score |
|------------|---------------|-------|
| Edgar      | Codd          | 92    |
| Patricia   | Selinger      | 85    |
| Donald     | Chamberlin    | 85    |

The `NOT IN` operator can also produce surprising results when NULL is involved. We should always check which columns are nullable when filtering. 

## Sorting and Filtering Summary

We can summarise the different parts of an SQL query.

**Conceptual Model of SQL clauses**

|Clause    | What does it do?                    |
|----------|-------------------------------------|
|FROM      |Where does the data come from?       |
|WHERE     |Which rows do I want?                |
|SELECT    |Which columns do I want?             |
|DISTINCT  |Remove duplicate result rows         |
|ORDER BY  |How should the rows be arranged?     |
|LIMIT     |How many rows should I return?       |
|OFFSET    |How many rows should I skip?         |
