So database design is our focus for the next two weeks. We have already been giving some consideration to the design of our tables. For example, when choosing data types and constraints for our columns, when identifying relationships and using foreign keys. All these choices were made so we would have well-designed database tables. This week is a deeper look at database design, thinking about the process of database design from start to finish, and the techniques that are used to create a well-designed database.

Regardless of the database, there are two basic principles that we always want to follow:-

Number one is that duplicate, or sometimes we say redundant, data is bad. Specifically duplicate text data is bad. Whenever we have the same piece of text e.g. a board game's title, a product name, a degree title being stored multiple times, it is often an indication that our database is poorly designed. Whenever we have duplicate data it increases the chances of inconsistencies, and it wastes space in our database.

The second principle, which is a bit more vague is the design should make sure the data is accurate and correct. We want to reduce the possibility of incorrect data being stored. The constraints we added to our board games table back in week 1 is a good example. We designed the table in a way to make sure the maximum number players is always greater than the minimum number of players.
