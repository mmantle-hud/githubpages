# Subqueries

A **subquery** is a query contained within another SQL query.

The following examples all use the Course Assessment Database to illustrate the different types of subquery.

## Scalar (Single Value) Subqueries

The simplest type of subquery to understand is one that retrieves a single (scalar) value. 

First, let's look at a simple query, and then look at how it can be used as a subquery.

The following query finds the weighting of the assessment with the highest weighting.

```sql
SELECT
    MAX(assessment_weighting)
FROM
    assessments;
```

| max | 
|-----| 
| 0.6 | 


There isn't anything new here, we have seen similar queries before. 

We can then use this query as a subquery (i.e. inside another query) to give the title of assessment that has the highest weighting. 

```sql
SELECT
    assessment_title,
    assessment_weighting
FROM
    assessments
WHERE
    assessment_weighting = (
        SELECT
            MAX(assessment_weighting)
        FROM
            assessments
    );
```
<p></p>
| assessment_title       | assessment_weighting | 
|------------------------|----------------------| 
| Programming Assignment | 0.6                  | 


- The subquery is placed inside parentheses (curved brackets).
- We call the query that contains the subquery the **outer query** or **main query**. 
- We call this type of subquery a scalar subquery because it returns a **single** value. 

Here's another example. 

Find the names of the students that scored higher than the average score for the 'Python Programming Concepts Quiz' (assessment 1).


```sql
SELECT
    s.given_name,
    s.family_name,
    sas.score
FROM
    students AS s
    INNER JOIN student_assessment_scores AS sas ON s.student_id = sas.student_id
WHERE
    sas.assessment_id = 1
    AND sas.score > (
        SELECT
            AVG(score)
        FROM
            student_assessment_scores
        WHERE
            student_assessment_scores.assessment_id = 1
    );
```

| given_name | family_name | score | 
|------------|-------------|-------| 
| Elizabeth  | Fong        | 85    | 
| Patricia   | Selinger    | 72    | 
| Tracy      | Chou        | 92    | 
| Brendan    | Eich        | 78    | 
| Håkon Wium | Lie         | 81    | 


This example is a little more complex as it also uses a join to show the names of the students.

## Multiple Rows, Single Value Subqueries

The previous subqueries each returned a single row with a single value. The following subqueries select single values, but multiple rows. 

Again we'll look at the subquery in isolation first. We can retrieve the IDs of certain degree types using `IN`.

```sql
SELECT
    degree_id
FROM
    degrees
WHERE
    degree_type IN ('BSc', 'MSc');
```

| degree_id | 
|-----------| 
| 1         | 
| 3         | 
| 4         | 
| 5         | 
| 6         |

Using this query as a subquery allows us to get the names of students on the BSc and MSc degrees.

```sql
SELECT
    given_name,
    family_name
FROM
    students
WHERE
    degree_id IN (
        SELECT
            degree_id
        FROM
            degrees
        WHERE
            degree_type IN ('BSc', 'MSc')
    );
```

| given_name | family_name | 
|------------|-------------| 
| Elizabeth  | Fong        | 
| Patricia   | Selinger    | 
| Tracy      | Chou        | 
| Radia      | Perlman     | 
| Tim        | Berners-Lee | 
| Brendan    | Eich        | 
| Håkon Wium | Lie         | 
| Jen        | Simmons     | 

Here's another example that finds students that haven't completed assignment 1.

```sql
SELECT
    given_name,
    family_name
FROM
    students
WHERE
    student_id NOT IN (
        SELECT
            student_id
        FROM
            student_assessment_scores
        WHERE
            assessment_id = 1
    );
```

| given_name | family_name | 
|------------|-------------| 
| Michael    | Stonebraker | 

An important point to note here is that `student_id` is part of the primary key and can't be NULL in the `student_assessment_scores` table, therefore this query will work fine. If `student_id` was nullable this query could return unexpected results. A more robust approach would be to use `EXISTS` (see an example further on). 


## Table Subqueries in the FROM Clause (Derived Tables)

Again, for the first example, we'll look at the subquery in isolation first. 

This query retrieves the scores of all the students that passed (i.e. they got a score of 40 or greater) for assessment 2, the 'Programming Assignment'.

```sql
SELECT
    score
FROM
    student_assessment_scores
WHERE
    score >= 40
    AND student_assessment_scores.assessment_id = 2;
```

| score | 
|-------| 
| 90    | 
| 68    | 
| 62    | 
| 88    | 
| 70    | 
| 52    | 
| 84    | 

We can place this query in the `FROM` clause, and select columns to retrieve. 

By placing the subquery in `FROM` the subquery becomes like a virtual table that we can select columns from or perform aggregations on. 


```sql
SELECT
    MIN(passing_scores.score) AS lowest_passing_score
FROM
    (
        SELECT
            score
        FROM
            student_assessment_scores
        WHERE
            score >= 40
            AND student_assessment_scores.assessment_id = 2
    ) AS passing_scores;
```

| lowest_passing_score | 
|----------------------| 
| 52                   | 

This is a simple example, we didn't really need to use the subquery (you may be able to think of simpler ways of getting the same result), but it shows how a subquery can be used in a `FROM` clause.

Let's have a look at a slightly more useful example. This query finds the number of students studying the most popular degree.

```sql

SELECT
    MAX(student_counts.student_count) AS largest_degree_size
FROM
    (
        SELECT
            students.degree_id,
            COUNT(*) AS student_count
        FROM
            students
        GROUP BY
            students.degree_id
    ) AS student_counts;
```

| largest_degree_size | 
|---------------------| 
| 3                   |

SQL doesn't allow us to perform nested aggregations e.g. `MAX(COUNT(*))`. Therefore, we do the aggregation in two steps. The subquery counts the students on each degree. The outer query finds the highest value. 

<!-- you'd typically reach for COUNT(column) specifically when you need to either ignore NULLs in that column, or (as in the LEFT JOIN case from before) avoid counting rows that only exist because of the join. -->

This example selects each student name and their highest score from the two assessments.


```sql
SELECT
    s.given_name,
    s.family_name,
    best_scores.max_score AS best_score
FROM
    students AS s
    INNER JOIN (
        SELECT
            student_id,
            MAX(score) AS max_score
        FROM
            student_assessment_scores
        GROUP BY
            student_id
    ) AS best_scores ON s.student_id = best_scores.student_id;
```

|------------|-------------|------------| 
| Håkon Wium | Lie         | 81         |

| Tracy      | Chou        | 92         | 
| Jen        | Simmons     | 48         |

| Patricia   | Selinger    | 72         | 
| Tim        | Berners-Lee | 52         | 
| Elizabeth  | Fong        | 90         | 
| Brendan    | Eich        | 84         | 



## Correlated Subqueries
Unlike a regular subquery that runs once and independently, a correlated subquery executes repeatedly, once for each row evaluated by the outer query. 

Again, we'll break this down to make it easier to understand. The following query gets the number of students studying the degree with an ID=1 (Data Science).

```sql
SELECT
    COUNT(*) AS student_count
FROM
    students
WHERE
    students.degree_id = 1;
```

| student_count | 
|---------------| 
| 2             | 

We can make this a subquery and replace the hard-coded ID of 1 with `degrees.degree_id` and the query will get linked to the outer query. 


```sql
SELECT
    degrees.degree_type,
    degrees.degree_title,
    (
        SELECT
            COUNT(*) AS student_count
        FROM
            students
        WHERE
            students.degree_id = degrees.degree_id
    ) AS student_counts
FROM
    degrees;
```

| degree_type | degree_title           | student_counts | 
|-------------|------------------------|----------------| 
| BSc         | Data Science           | 2              | 
| BA          | Computing in Business  | 2              | 
| BSc         | Computing              | 3              | 
| BSc         | Software Engineering   | 2              | 
| BSc         | Information Technology | 0              | 
| MSc         | Computing              | 1              | 

<p></p>

The subquery retrieves the count for a specific degree. 

The key thing here is the subquery will be executed six times. Once for each degree in the database. Each time the subquery is run, a different `degree_id` is passed in. If we have many rows in the outer query this can have performance (execution speed) implications. 

### EXISTS
`EXISTS` checks whether a subquery returns any rows at all. It doesn't care about the values returned, only whether at least one row matches. 

The following query returns the titles of all the degrees that have at least one student enrolled on the course (BSc Information Technology has no students currently enrolled). 

```sql
SELECT
    d.degree_type,
    d.degree_title
FROM
    degrees AS d
WHERE
    EXISTS (
        SELECT
            *
        FROM
            students AS s
        WHERE
            s.degree_id = d.degree_id
    );
```

| degree_type | degree_title           | 
|-------------|------------------------| 
| BSc         | Data Science           | 
| BA          | Computing in Business  | 
| BSc         | Computing              | 
| BSc         | Software Engineering   | 
| MSc         | Computing              |

For each degree in turn we select the students studying the degree. `EXISTS` returns true if at least one row is returned and false if none are returned. There is also a `NOT EXISTS` that simply flips the logic. 

Here's another correlated subquery. This query selects the names of all the students that scored higher than their degree average for assignment 1.

```sql
SELECT
    s.student_id,
    s.given_name,
    s.family_name,
    sas.score
FROM
    students AS s
    INNER JOIN student_assessment_scores AS sas ON s.student_id = sas.student_id
WHERE
    sas.assessment_id = 1
    AND sas.score > (
        SELECT
            AVG(sub_sas.score)
        FROM
            student_assessment_scores AS sub_sas
            INNER JOIN students AS sub_s ON sub_sas.student_id = sub_s.student_id
        WHERE
            sub_sas.assessment_id = 1
            AND sub_s.degree_id = s.degree_id 
    );
```

| student_id | given_name | family_name | score | 
|------------|------------|-------------|-------| 
| 1          | Elizabeth  | Fong        | 85    | 
| 5          | Tracy      | Chou        | 92    | 
| 8          | Brendan    | Eich        | 78    | 

## Using HAVING

We can also use subqueries in a `HAVING` clause.

This query finds all the degrees where the average score for the degree is higher than the average student score for assignment 2

```sql
SELECT
    s.degree_id,
    AVG(sas.score) AS degree_average
FROM
    students AS s
    INNER JOIN student_assessment_scores AS sas ON s.student_id = sas.student_id
WHERE
    sas.assessment_id = 2
GROUP BY
    s.degree_id
HAVING
    AVG(sas.score) > (
        SELECT
            AVG(score)
        FROM
            student_assessment_scores AS sub_sas
        WHERE
            sub_sas.assessment_id = 2
    );
```

| degree_id | degree_average | 
|-----------|----------------| 
| 1         | 79             |

## Often We Can Avoid Subqueries

Often it is possible to re-write a query so it doesn't use a subquery.

Let's take the first example we looked at, this finds the assessment with the highest weighting.

```sql
SELECT
    assessment_title,
    assessment_weighting
FROM
    assessments
WHERE
    assessment_weighting = (
        SELECT
            MAX(assessment_weighting)
        FROM
            assessments
    );
```

This query can easily be re-written using `ORDER BY` and `FETCH FIRST`

```sql
SELECT
    assessment_title,
    assessment_weighting
FROM
    assessments
ORDER BY
    assessment_weighting DESC
FETCH FIRST
    1 ROWS WITH TIES;
```

Most people would think the second version is clearer and easier to read when compared to using a subquery. 

Here's another example.

Earlier we used a subquery to get the names of students on the BSc and MSc degrees.

```sql

SELECT
    given_name,
    family_name
FROM
    students
WHERE
    degree_id IN (
        SELECT
            degree_id
        FROM
            degrees
        WHERE
            degree_type IN ('BSc', 'MSc')
    );
```

This can be re-written using `INNER JOIN`.

```sql
SELECT
    s.given_name,
    s.family_name
FROM
    students AS s
    INNER JOIN degrees AS d ON s.degree_id = d.degree_id
WHERE
    d.degree_type IN ('BSc', 'MSc');
```

So when should we use subqueries and when should we use joins? Joins are generally preferred as we can show columns from multiple tables in the output. Subqueries cannot easily pass data up to the outer query. 

However, sometimes subqueries are preferred. For example, if we are simply using the subquery to filter results (like the previous query) this can be easier for humans to read. 

Beyond readability there are also performance considerations, how fast the queries run. For example correlated subqueries re-execute for each outer row and can be much slower than an equivalent join, once tables get large.
