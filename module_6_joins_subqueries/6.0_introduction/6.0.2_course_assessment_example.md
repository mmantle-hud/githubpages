# Course Assessment Database
This database will be used to provide examples in the reading for this week. Have a quick look at it now, and then refer back to this page to help you understand the examples presented in the reading this week. 

Back in the first week of the course we looked at a course assessment example that used a single table. 

Now that we know about relationships and the principles of database design, we can replace the simple, single table design with something that is more fit for purpose. 

**Course Assessment: Physical ERD**

<pre class="mermaid">
erDiagram
    degrees ||--o{ students : ""
    students ||--o{ student_assessment_scores : ""
    assessments ||--o{ student_assessment_scores : ""

    degrees {
        INT degree_id PK
        VARCHAR(255) degree_type "NOT NULL"
        VARCHAR(255) degree_title "NOT NULL"
    }

    assessments {
        INT assessment_id PK
        VARCHAR(255) assessment_title "NOT NULL"
        TEXT assessment_description "NOT NULL"
        NUMERIC(3,2) assessment_weighting "NOT NULL"
    }

    students {
        INT student_id PK
        VARCHAR(255) given_name "NOT NULL"
        VARCHAR(255) family_name "NULL"
        INT degree_id FK "NOT NULL"
    }

    student_assessment_scores {
        INT student_id PK, FK
        INT assessment_id PK, FK
        INT score "NOT NULL"
    }
</pre>

This database is designed for a tutor to help them assess a _single_ course e.g. the tutor teaching CFM7101 Calculus could use this database to store the details of the assessments for the course, the students taking their course, the degrees these students are studying, and the scores they achieve in the course assessments.
