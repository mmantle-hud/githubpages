# HTML and CSS Best Practices

## Correctly Structured Documents
When we looked at HTML we considered an example of an element that wasn't nested correctly. The `<h2>` and `<em>` elements overlap. 

```html
<h2>Welcome <em>to HTML</h2></em>
```
We said the HTML was incorrectly structured; we hadn't obeyed the rules of HTML. 

Why is this important? If we viewed this HTML in a browser it would look fine. 

Browsers are forgiving of malformed HTML. Consequently, the rendered result may appear correct, 

However, correctly structuring documents is important. Here are two reasons why:
1. Users with visual disabilities may use a screen reader to experience the web. A screen reader reads out the contents of a web page for a user that can't see the words and images. Screen readers benefit from correctly structured pages with properly nested elements and clearly organised contents.
2. Search engines such as Google look through the contents of (or crawl) webpages so that relevant pages can be recommended when the user enters a search term. Correctly structur pages will it easy for automated tools to extract the contents of the page. 

We can use a service such as the [W3C Validator](https://validator.w3.org/) to check our pages have been correctly structured. We call this validating a web page. The validator will report on any errors it finds or give feedback that the page is 'valid' i.e. correctly structured.

## Accessibility
Accessibility is about designing webpages for users with disabilities. We have seen a number of examples in the reading from this week.
- Writing correctly structured HTML. This is important, not only for users with screen readers, but also for users with motor disabilities. Users with a motor disability might navigate the web using the keyboard only (no mouse). If we structure content correctly, users can use the 'tab' key to move through the different parts of a page. 
- Using the `alt` attribute when inserting images. 
- Only using images when they add to the content of the page. 

There are other considerations we haven't covered. Here are some examples.
- Skip links. Allowing the user to skip past navigation links and jump straight to the page content when navigating using the keyboard.
- Colour contrast. When choosing CSS colours we should make sure there is sufficient contrast between colours, and we should take into account users that may be colour blind.
