# Indexes Lab
Follow theses steps to get a feel for how indexes can speed up queries.

## Create a test table
In _sql/indexes.sql_ add the following SQL to create a simple table

```sql
-- 1. Create a clean test table
DROP TABLE IF EXISTS demo_students;

CREATE TABLE demo_students (
    student_id INT,
    given_name VARCHAR(255),
    family_name VARCHAR(255),
    CONSTRAINT pk_demo_students PRIMARY KEY (student_id)
);
```
I haven't added a primary key 

## Populate the table with fake data
Populate this table with 499,999 rows of fake data. 
```sql
-- 2. Insert 499,999 filler rows
INSERT INTO demo_students (student_id, given_name, family_name)
SELECT
    g.id,
    'John',
    'FillerLastName'
FROM generate_series(1, 499999) AS g(id);
```
`generate_series` is a Postgres command that will generate a sequence of integers for us. In this example from 1 to 499,000.
Check this has worked e.g. `SELECT * FROM demo_students LIMIT 100;` or `SELECT COUNT(*) FROM demo_students;`

## Insert a target row
This is the row we will search for. 
```sql
-- 3. Insert one target row
INSERT INTO demo_students (student_id, given_name, family_name)
VALUES (500000, 'Alice', 'Smith');
```
Again, check this has worked e.g. `SELECT COUNT(*) FROM demo_students;`

## Make sure PostgreSQL has up-to-date statistics
```sql
-- 4. Collect statistics on the demo_students table
ANALYZE demo_students;
```
`ANALYZE` tells PostgreSQL to collect statistics about the data in the table e.g. how many rows and how the values are distributed. 

## Perform a search without an index
```sql
-- 5. Search without an index
EXPLAIN (ANALYZE, BUFFERS)
SELECT *
FROM demo_students
WHERE family_name = 'Smith';
```
`EXPLAIN (ANALYZE, BUFFERS)` runs the query that follows and tells us how Postgres ran the query. You should get some output similar to the following:

| QUERY PLAN                                                                                                                 | 
|----------------------------------------------------------------------------------------------------------------------------| 
| Gather  (cost=1000.00..6789.27 rows=1 width=24) (actual time=62.738..88.983 rows=1 loops=1)                                | 
|   Workers Planned: 2                                                                                                       | 
|   Workers Launched: 2                                                                                                      | 
|   Buffers: shared hit=3185                                                                                                 | 
|   ->  Parallel Seq Scan on demo_students  (cost=0.00..5789.17 rows=1 width=24) (actual time=20.805..20.805 rows=0 loops=3) | 
|         Filter: ((family_name)::text = 'Smith'::text)                                                                      | 
|         Rows Removed by Filter: 166666                                                                                     | 
|         Buffers: shared hit=3185                                                                                           | 
| Planning:                                                                                                                  | 
|   Buffers: shared hit=19                                                                                                   | 
| Planning Time: 1.802 ms                                                                                                    | 
| Execution Time: 89.010 ms                                                                                                  | 

Your output might not have identical results. Here are some key aspects to note
- Postgres executed a parallel sequential scan. 
- Planning time is the time Postgres used to decide how to run the query.
- Execution time is the time it took to execute the query.

## Create The Index
```sql
-- 6. Create an index
CREATE INDEX idx_demo_family_name
ON demo_students(family_name);
```
Use SQLTools to confirm the index has been created. If you find the `demo_students` table, there should be an indexes directory where you can confirm the index has been created.

## Update The Statistics Again
```sql
-- 7. Update statistics
ANALYZE demo_students;
```

## Repeat the Search Using the Index
```sql
-- 8. Search with the index
EXPLAIN (ANALYZE, BUFFERS)
SELECT *
FROM demo_students
WHERE family_name = 'Smith';
```
You should get some output similar to the following:
| QUERY PLAN                                                                                                                          | 
|-------------------------------------------------------------------------------------------------------------------------------------| 
| Index Scan using idx_demo_family_name on demo_students  (cost=0.42..4.44 rows=1 width=24) (actual time=0.141..0.146 rows=1 loops=1) | 
|   Index Cond: ((family_name)::text = 'Smith'::text)                                                                                 | 
|   Buffers: shared hit=1 read=3                                                                                                      | 
| Planning:                                                                                                                           | 
|   Buffers: shared hit=19 read=1                                                                                                     | 
| Planning Time: 0.693 ms                                                                                                             | 
| Execution Time: 0.207 ms                                                                                                            | 

Again, your results won't be identical. However, you should get confirmation that
- The index has been used _Index Scan using idx_demo_family_name on demo_students_
- The execution time is faster

## Clean up by removing the index
```sql
-- 9. Remove the index
DROP INDEX idx_demo_family_name;
```
