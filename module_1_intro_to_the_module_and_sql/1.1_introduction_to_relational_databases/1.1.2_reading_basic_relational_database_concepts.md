# Basic Relational Database Concepts and Terminology
The following describes key relational database concepts and terminology we will use on the course. 

## Table
Relational Databases work by storing data in tables. Here's an example of a relational database table.

**students**

|student_id (PK) | given_name | family_name   | degree                  | score |
|----------|------------|---------------|-------------------------|-------|
|1         | Edgar      | Codd          | Computing               | 92    |
|2         | Elizabeth  | Fong          | Data Science            | 67    |
|3         | Donald     | Chamberlin    | Information Technology  | 85    |
|4         | Patricia   | Selinger      | Computing               | 85    |
|5         | Michael    | Stonebraker   | Data Science            | 34    |
|6         | Jennifer   | Widom         | Computing               | 47    |

<p></p>

- Tables store data about entities. **An entity is a type of thing from the real world** e.g. students, movies, countries, products, orders. Each table stores data about one entity. 
- The table **columns** (`given_name`, `family_name`, `degree` etc.) specify the data type and labels for the individual pieces of data that will be stored.
- Each **row** represents one instance, or a specific example, of the entity e.g. the second row of the `students` table stores data about a student called _Elizabeth Fong_. They are studying the _Data Science_ degree and have a score of _67_. We also we use the term **record** to describe a row. 
- Each individual intersection of a row and a column stores a single data value. This individual cell is referred to as a **field** (or a **field value**).
 
In Codd's original paper different terms (relation, attribute and tuple) were used to describe many of these ideas. These terms had their roots in mathematical concepts. Many people still use these terms, especially when discussing the theoretical underpinnings of relational databases. 

**Database Terminology**

|Common Developer Term | Relational Theory / Mathematical Term                |
|---------------------------|---------------------------------------------|
|Table	                    |Relation (A set of related data)             |
|Column 	                |Attribute (A characteristic of the data)     |
|Row / Record	            |Tuple (An ordered list of values)            |


However, for most people table, column and row are more intuitive to use, and this is the language used by most developers and database industry professionals.

Don't be confused if you see these alternative terms used in books and articles. 

## Database
**A database is a collection of related tables**. For example, an e-commerce web application would store data in a database. Within the database we would have a number of different tables e.g. for products, users, orders, reviews etc. 

## Relational Database Management System (RDBMS)
An RDBMS e.g. PostgreSQL manages multiple databases. An organisation may have a single PostgreSQL installation, and this installation would host multiple databases. For example, a finance database, a marketing database and customer portal database. 

The RDMS handles security; which users can access which databases and what actions they can perform. The RDBMS also takes care of aspects such as backing up data, crash recovery and logging.

We can view the relationship between the RDBMS, databases, tables, rows and fields as being hierarchical.
