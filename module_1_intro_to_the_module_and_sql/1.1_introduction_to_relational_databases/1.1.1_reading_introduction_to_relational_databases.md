# Introduction to Relational Databases and PostgreSQL

## What is data?
Data is a collection of raw facts. **A single piece of data is one fact about something we are interested in**. For example, a number, a word, a symbol. The following are all examples of data.
- 67
- 'Computing'
- TRUE
- 1970-07-29

## What is a database?
**A database is an organised collection of data**. A structured way of storing many individual facts so they can be easily found, used, and updated.

In a relational database, this means storing data in tables.

## A Brief History of Databases

In the early years of computing, data was stored on magnetic tape. Data was read sequentially as tape passed over a tape head. It wasn't easy to move from one piece of data to another unless the records were next to each other. If we wanted to modify or edit the data we would read data from one tape and write to a completely new tape. 

<!-- We couldn't simply insert data into the middle of tape.  -->

In the late 1960s hard disk drives became widespread and the location of a piece of data was less important, any location on a disk could be accessed in milliseconds. It was this invention that provided the conditions for the creation of modern databases.

The first **Database Management Systems (DBMSs)** came along in the mid to late 1960s. 

A database management system is software that provides a convenient way for users to interact with data. We can think of a DBMS as a layer over the top of the data. As users of the database we don't interact with the data directly, we simply issue commands to the DBMS allowing us to easily create, retrieve, edit and delete data. 

- Some DBMS such as IBM's Information Management Systems (IMS) used a hierarchical structure. 
- Other DBMS, such as CODASYL used a more flexible network structure.

Both these systems made processing data easier. However, both systems struggling with data duplication and redundancy. 

They were also 'pointer based'. They stored the physical location of a linked piece of data as part of the record. This made them brittle and inflexible. If data needed to be moved on disk, existing references no longer worked.


### Relational Databases
Edgar F. Codd, a computer scientist working at IBM, addressed these weaknesses in a paper titled "*A Relational Model of Data for Large Shared Data Banks*" (1970). In this paper, Codd introduced the key ideas that formed the basis for relational databases. He proposed an approach to databases (he called them data banks) that was much more user-friendly. 
- Codd proposed the idea of storing data in tables.
- Codd argued the logical structure of data, the external representation, should be separate from the internal representation i.e. how it is stored physically on disk. As users, we should only have to worry about the external representation. 
- Codd argued that people should be able to ask questions about data using a more natural language. This idea led directly to SQL, which is the language used by all major relational database management systems today.

Codd's ideas were radical at the time. It took until the 1980s for the relational model to gain widespread acceptance.

This was partly due to skepticism. Codd's ideas were theoretical, people had to invest time and resources into building systems that used the relational model and were reliable. 

It was also a computing resources issue. Hierarchical and network databases had a simplicity, following pointer links between records. The relational model used tables that needed to be loaded into memory. Computers needed sufficient RAM to load tables and perform operations. 

Eventually the relational model took over the world of computing and became the dominant form of database. In the 1990s or early 2000s, if someone used the term database, they almost always meant a relational database. Even today, the relational model remains the most widely used and dominate form of database. 

You may have used or heard of one of the following popular Relational Database Management Systems (RDBMS).
- Oracle
- MySQL
- SQL Server
- PostgreSQL
- SQLite

Relational Databases aren't the only type of database. For example, NoSQL databases and graph databases are also popular. Once we fully understand relational databases, we will compare the relational model to some of these other types of database. 

## PostgreSQL
In many ways it isn't important which RDBMS you learn. They are all based on Codd's relational model, and they all use SQL as the language for interacting with databases.  

We will use PostgresSQL. There are two good reasons for choosing PostgreSQL:

1. It is widely used in industry. [Many large tech firms such as Reddit, Instagram and Spotify currently use PostgreSQL, or have used it in their recent past][1].  


2. PostgreSQL is open source. No company owns it. It is free to use, and the source code is publically available. An active community of developers decide what new features need to be added. They then work together to develop them.
