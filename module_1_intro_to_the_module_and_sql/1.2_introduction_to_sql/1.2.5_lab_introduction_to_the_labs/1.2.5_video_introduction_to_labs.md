# Introduction to the Labs
We are going to work with PostgreSQL through Coursera's lab environment. 

To start a lab you simply click launch lab

The lab environments we will use is a VS Code environment.

VS Code is a very popular lightweight code editor. It's widely used in industry by software engineers, web developers and data scientist. 

It supports a wide range of web programming languages such as HTML CSS and JavaScript, general purpose programming languages such as Java and Python, it can also run Jupyter notebooks. We are going to use it as an SQL editor, and later on in the course to build web applications.


When VS Code first opens you will need to select the project folder. 


Now we are in the correct folder, you should get a notification in the bottom right corner telling you 'Your application is running on port 5432 is available.' 

In the background, the lab environment installs PostgreSQL and sets-up a database for us to use. This message is simply confirmation that PostgreSQL has been installed and is ready to use. 

There will always be README file, this will give instructions for the lab work, telling you which files you need to look at and the exercises you need to complete.

Most of our lab work will involve writing and executing SQL code. We will write our code in files with a dot sql extension. Usually I will provide these for you. You simply need to add your code inside these files.  

To set-up our database tables, we will use a file named schema.sql. This will contain SQL CREATE TABLE statements.

To populate tables with data, we will use a file named seeder.sql. This will contain SQL INSERT statements. 

Other queries such as SELECT and UPDATE will be written in a file name queries.sql.

We can open files by clicking on them or dragging them onto the main editor area. 


You should recognise most of the SQL code in this schema file. 

The bits in gray are comments. Comments are ignored when executing SQL scripts. I will use comments to explain pieces of SQL code or to present questions and exercises for you to complete.

The only bit we haven't already explained is the DROP TABLE command. This is simply an instruction to Postgres to delete a table. We add DROP table statements at the top of our schema files to ensure the script can run repeatedly from a clean slate without crashing. It simply wipes out existing tables so we can start again. 

To run the SQL code we simply select "Run on active connection"

A new panel will open that will show the results of our queries. 

This is a create statement so it doesn--'t return a resultset. There is no data to display. However, we can click on 'CONSOLE' and get confirmation the query has executed successfully. 

If we have errors in our SQL, the results panel will let us know and report on the error.

For example, if I spell varchar incorrectly, the results panel lets me know. 

Now let's run the seeding script. 

Again, we can simply select "Run on active connection" and we get confirmation the commands have successfully executed. 

Again, there is some SQL we haven't previously discussed. The truncate command deletes all rows from an existing table, leaving the table's structure completely intact. We can use it to reset the table's content without destroying the table itself. 
 


Lastly, let's run some SELECT queries. Again, we can click on "Run on active connection". This time our queries do return a resultset, and these are displayed in the results panel. 

Sometimes we will have lots of queries in an SQL file. We can run individual queries by selecting the query, right-clicking and selecting "Run selected query". Alternatively, we can use a keyboard shortcut by selecting control and 'e' twice.



 VS Code works with PostgreSQL using an extension called SQLTools. 

We can use this extension to explore our database. 

From the activity bar on the right, we can select the cylinder icon. This is SQLtools. 

We can then select our connection, I've called this Coursera Labs DB, select our database, I've set up a database called coursedb, then schemas, public, tables and then we can explore our tables. We can see the columns and data types. 

If we click on the "show table records" icon, SQLtools will quickly run a select statement to show our table data. 

This is especially useful when you are working with a new database you didn't create yourself. Often in the labs I will set-up a database for you and you will run select statements using the database. Being able to explore these unfamiliar tables can really help when trying to construct successful queries. 

Each week's lab work will use this same set-up, using vs code as the editor and the SQLTools extension, and what I have demonstrated here should be enough to get you up and running in completing your lab work.
